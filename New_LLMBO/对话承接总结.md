# New_LLMBO 对话承接总结

## 1. 当前结论

这轮工作的主结论已经比较明确：

- 严格 baseline 是可信的，HV 已修到单调，`hv_violations = 0`
- `LLM warmstart` 本身是有效的
- 持续把 LLM 耦合进 `GP / AF` 的方法目前还不够稳
- 在更硬的 benchmark 下，当前最好的主配置仍然是：

```json
{
  "n_warmstart": 3,
  "n_random_init": 3,
  "enable_iterative_guidance": false,
  "enable_gp_llm_coupling": false,
  "enable_acq_prior_coupling": false,
  "enable_proposal_sampler": false
}
```

也就是：

- LLM 只负责 warmstart
- 后续 BO 完全使用 plain EI

## 2. 已完成的关键工作

### 2.1 HV / Pareto / 约束一致性修复

已经完成：

- 修复 HV 实现，消除非单调问题
- Pareto 去重
- 统一 `dSOC1 + dSOC2` 约束语义
- `lambda` 增加 clamp / annealing
- prompt 中加入 `0.65` 安全裕度说明

关键文件：

- `DataBase/database.py`
- `utils/constants.py`
- `llmbo/gp_model.py`
- `llm/llm_interface.py`
- `llm/templates/warmstart/detailed.txt`
- `tests/test_hv_and_coupling.py`

当前状态：

- 多组实验里 `hv_violations = 0`

### 2.2 Proposal sampler V1

已经实现小样本版 weighted GMM proposal sampler。

关键文件：

- `llmbo/proposal.py`
- `tests/test_proposal_sampler.py`

实现特点：

- weighted KMeans + 加权经验协方差
- 支持 `fit / sample / score`
- 采样后做 bounds repair 和 `dSOC` repair

当前判断：

- proposal V1 已接通
- 但在真实 benchmark 下暂时没有稳定带来收益

### 2.3 Acquisition prior 路线

已经实现一条新路线：不直接改 GP posterior，而是在 acquisition 上加入 prior bonus 和 risk penalty。

关键文件：

- `llmbo/acquisition.py`
- `llmbo/optimizer.py`
- `tests/test_acquisition_prior.py`

实现点：

- 新增 `AcquisitionPrior`
- 对 guidance / proposal 只做软 bonus
- 对贴近边界和不安全电流型候选做 risk penalty
- 对 sigmoid 做数值稳定化，避免 `exp overflow`

当前判断：

- 这条线在短预算实验里一度有希望
- 但在更硬 benchmark 下没有守住优势

## 3. Baseline 是怎么实现的

### 3.1 严格 baseline

这是完全不使用 LLM 的版本：

```json
{
  "n_warmstart": 0,
  "n_random_init": 6,
  "enable_iterative_guidance": false,
  "enable_gp_llm_coupling": false,
  "enable_acq_prior_coupling": false,
  "enable_proposal_sampler": false
}
```

本质流程：

- 随机初始化
- 每轮取一个 `w_vec`
- 对三目标做 augmented Tchebycheff 标量化
- 拟合单输出 Matern GP
- 用普通 EI 选点

关键路径：

- `llmbo/optimizer.py`
- `llmbo/gp_model.py`
- `llmbo/acquisition.py`

### 3.2 当前更重要的对照 baseline

这是当前最值得对照、也最强的实际 baseline：

```json
{
  "n_warmstart": 3,
  "n_random_init": 3,
  "enable_iterative_guidance": false,
  "enable_gp_llm_coupling": false,
  "enable_acq_prior_coupling": false,
  "enable_proposal_sampler": false
}
```

也就是：

- LLM 只做 warmstart
- 后续 BO 完全退回 plain EI

后面提到的 `plain EI`，如果没有特别说明，都是指这组。

## 4. 关键实验脉络

### 4.1 早期结论

已经确认过：

- `warmstart + plain EI` 通常优于严格 baseline
- 早期版本的 `LLM-EI / GP mean coupling` 经常拉低性能

参考：

- `optimized_experiments/ordinary_ei_comparison/report.json`
- `optimized_experiments/ei_mechanism_ablation/report.json`

### 4.2 Proposal V1 实验

第一版 proposal 在 3-seed / 5-iteration 下没有带来收益。

参考：

- `optimized_experiments/proposal_batch_v1/report.json`

结论：

- `warmstart + plain EI` 仍优于 `warmstart + proposal`
- proposal V1 不适合直接升为默认

### 4.3 Acquisition prior 初轮实验

在较短预算实验中，这条线看起来很有希望。

参考：

- `optimized_experiments/acq_prior_comparison_v1/report.json`

当时结果大致为：

- `baseline_ei`: `0.3306`
- `warmstart_plain_ei`: `0.3358`
- `warmstart_acq_prior`: `0.3461`
- `warmstart_acq_prior_proposal_light`: `0.3569`
- `warmstart_old_gp_coupling`: `0.3556`

当时的判断是：

- `acq prior + proposal light` 暂时最好
- `old GP coupling` 也比预期更稳

### 4.4 更硬 benchmark 的最终结论

后来又做了更硬的一轮：

- 只比 3 组：
  - `warmstart_plain_ei`
  - `warmstart_acq_prior_proposal_light`
  - `warmstart_old_gp_coupling`
- `5` seeds
- `8` 轮 BO

参考：

- `optimized_experiments/acq_prior_focus_v2/report.json`

结果：

- `warmstart_plain_ei`: mean HV `0.3644`
- `warmstart_old_gp_coupling`: mean HV `0.3616`
- `warmstart_acq_prior_proposal_light`: mean HV `0.3445`

相对 `plain EI`：

- `old_gp_coupling`: `-0.78%`
- `acq_prior_proposal_light`: `-5.46%`

结论：

- 当前最可靠的主配置是 `warmstart_plain_ei`
- `old_gp_coupling` 接近 plain EI，仍值得保留为次优实验线
- `acq_prior + proposal light` 在长预算下没有守住优势

## 6. 一个重要提醒：代码默认值 != 当前最佳实验配置

需要特别注意：

- 当前代码默认值已经被改过
- 但默认值并不完全等于当前实验最优配置

例如当前 `optimizer.py` 的默认配置里，曾经设成：

- `enable_gp_llm_coupling = false`
- `enable_acq_prior_coupling = true`

但从最新 benchmark 看：

- `enable_acq_prior_coupling = true` 并不是当前最优主路径

所以如果下一个对话继续做实验，请显式覆盖配置，不要只依赖默认值。

## 8. 已知问题与风险

### 8.1 真实 API 连接波动

真实 API 实验里出现过：

- `Connection error`
- 重试后仍失败

这会给带 guidance 的实验组增加额外噪声。后续如果继续做高置信 benchmark，建议：

- 增强实验级缓存
- 或至少把失败重试情况计入统一日志

### 8.2 Proposal V1 仍然偏弱

虽然 proposal 已能工作，但当前问题是：

- 注入候选池后容易拖性能
- 即使轻量注入，在更长预算下也没有稳定赢过 plain EI

### 8.3 Old GP coupling 还不能彻底放弃

虽然当前主推是 plain EI，但从 `5` seed / `8` 轮结果看：

- `old_gp_coupling` 只比 plain EI 低 `0.78%`

所以它仍值得保留为次优研究线，而不是完全删除。

## 9. 下一步最值得继续的方向

### 方向 A：固化当前最优主配置

目标：

- 把 `warmstart_plain_ei` 固化成标准实验模板
- 让 README / 配置模板 / 默认实验脚本和当前最好实践一致

### 方向 B：继续专攻 old GP coupling

因为它目前最接近 plain EI。

下一步可尝试：

- 进一步调低 `lambda_max`
- 调整 guidance 到 grid / point 的权重形状
- 只在前半程启用 coupling，后半程退火到 0

### 方向 C：如果继续做 prior 路线，不要直接沿用当前版本

如果还想继续探索 `acq prior`，建议：

- 暂时关掉 proposal bonus，只做 risk penalty 的纯 ablation
- 或把 proposal 只作为 reranker，不直接进入最终 score
- 重点检查 prior 权重是否过强、proposal score 是否和真实 improvement 对齐不足
